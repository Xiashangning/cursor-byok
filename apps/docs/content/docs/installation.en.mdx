## Download the app

Go to the [latest release page](https://github.com/leookun/cursor-byok/releases/latest) and download the installer for macOS, Windows, or Linux.

<Callout type="info">
Prefer the latest stable release. The release page lists the installers and release notes for each version.
</Callout>

## First launch

<Steps>

<Step>

### Open Cursor Settings

After launching the app, go to **Cursor Settings**. If the local CA has not been initialized, the page shows an initialization entry.

</Step>

<Step>

### Initialize the local CA

Click **Initialize CA**. The local CA is used to inspect HTTPS requests from Cursor on your device; its files never leave your machine.

When the system asks for authorization, follow the instructions shown in the app to complete the trust step in your terminal, then return to the app and click **I have initialized, refresh**.

</Step>

<Step>

### Add your first model

Click **Add Model**, choose the OpenAI or Anthropic type, fill in the upstream service parameters, and save. See [Model Configuration](./model-configuration.mdx) for details on each field.

</Step>

<Step>

### Run the connectivity test

Click **Test** on the model. Once the test passes, the model appears in Cursor's model list.

</Step>

<Step>

### Completely restart Cursor after an upgrade or first setup

After upgrading Cursor or configuring a model for the first time, **quit Cursor completely and restart it once**. Closing only the window is not enough; make sure the Cursor process has stopped before opening it again.

</Step>

<Step>

### Start a new conversation

After Cursor restarts, start a new conversation and select your configured model from the model list. Do not continue a conversation opened before setup, and do not select **Auto**.

</Step>

</Steps>

## Remote SSH windows

When Cursor opens a Remote SSH window while Cursor Byok integration is enabled, the desktop app automatically provides the same proxy endpoint on the remote host:

```text
remote 127.0.0.1:<proxy port>
    └── SSH RemoteForward ──> local 127.0.0.1:<proxy port> ──> Cursor Byok
```

The app writes an isolated SSH configuration under its managed data directory and points Cursor Remote SSH at it. Your existing SSH configuration is included unchanged and restored when Cursor Byok stops. The remote listener is loopback-only, and connection setup fails if that port cannot be reserved; this prevents Cursor from silently using an unrelated service.

Before Cursor's remote server starts, the same SSH session copies the local CA certificate into the remote user's private Cursor Byok directory, exports the proxy and certificate environment, installs `uv` when necessary, and runs Semble's documented unattended Cursor MCP installer. Cursor then starts the Semble MCP server on the remote host, so code search reads the remote filesystem instead of looking for remote paths locally.

The bootstrap also synchronizes personal Agent Skills from the local `~/.cursor/skills/` and `~/.agents/skills/` directories. Cursor currently defines a skill as a directory containing `SKILL.md`, with optional scripts, references, and assets beneath it. Project skills under `.cursor/skills/` or `.agents/skills/` are already part of the Remote SSH workspace, so Cursor Byok does not copy them.

Personal skills are read when each new Remote SSH connection starts and transferred through the encrypted SSH reverse tunnel. They are installed under the reserved remote directory `~/.cursor/skills/cursor-byok-synced/`; `~/.cursor/skills/` takes precedence over `~/.agents/skills/` when both local roots contain the same skill name. A same-named skill already owned by the remote user in either user-level directory is preserved and takes precedence. The managed directory is rebuilt after a complete download, so locally deleted skills disappear on the next connection while unrelated remote content is never removed. Symlinks are skipped rather than followed. On Unix remotes, directories are private to the user, regular files use mode `0600`, and executable scripts use `0700`; Windows remotes use the ACL inherited from the remote user's profile.

Skill download, scanning, or installation errors are reported in the Remote SSH output but do not block the SSH connection. The previous complete managed copy remains in place when staging fails.

Remote SSH setup requires:

- `AllowTcpForwarding yes` on the remote SSH server;
- Bash plus `curl` on Linux/macOS remotes, or PowerShell on Windows remotes;
- network access to Astral, PyPI, and Hugging Face on first setup so `uv`, Semble, and its model can be downloaded;
- a correct `remote.SSH.remotePlatform` entry for Windows hosts so the PowerShell startup path is selected.

After enabling Cursor Byok or changing its proxy port, close and reopen existing Remote SSH windows. A first connection can take longer while Semble is installed. If installation cannot complete, the Cursor connection continues and reports the Semble error in the Remote SSH output.

## Verify the installation

After configuration, confirm that:

- The Cursor Settings page no longer shows the CA initialization prompt.
- At least one model passes the connectivity test.
- Cursor Byok stays running.
- Cursor has been quit completely and restarted once.
- You started a new conversation instead of continuing one opened before setup.
- The configured display name shows up in Cursor's model list.

If any of these steps fail, head to [Frequently Asked Questions](./faq.mdx).

## Updates

Check for new versions in the app settings, or visit [GitHub Releases](https://github.com/leookun/cursor-byok/releases/latest) directly. You do not need to delete existing model configurations before updating.
